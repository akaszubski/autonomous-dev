Receipt envelope: exact `schema,case,observation,decision,tool_version,
dependency_digests`; duplicate/unknown envelope keys refuse. Observation retains
the existing comparator fields `python,python_version,target,subject_digest,
collect_exit,run_exit,selected_count,nonce,selected`, adding the above resolved
metadata without another envelope. Original raw field types and IDs survive.
Canonical serialization is deterministic UTF-8 JSON with no non-finite numbers.
One run produces one complete receipt on stdout; diagnostics go to stderr and
sensitive raw capture stays private/bounded. No partial receipt can pass.

`PASS` means the selected case's required facts and expected outcome agree,
including a correctly observed expected refusal. `FAIL` is an observed
contradiction; `UNMEASURED` is required evidence/identity/correlation unavailable;
`ERROR` is a failed instrument or malformed/unreadable input. Non-PASS never
passes an enforcement boundary. Leaf invocation status is0 only for a complete
PASS receipt,1 for a completed FAIL/UNMEASURED and2 for ERROR; actual child exit
is separately preserved and never overwritten by formatting or the leaf exit.
The external F0 comparator's OK is agreement, not product PASS or promotion.
